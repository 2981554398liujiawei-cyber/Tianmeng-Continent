# 成人内容边界（Intimacy Rules）

> 依据任务卡 TM-P2-007 第 37 节（§37 Intimacy Rules）编制，为 Design Bible 成人内容红线文档。
> 标签规范：`[CANON]`=已上线实现；`[PLANNED]`=未来规划；`[UNKNOWN]`=无法核实。
> 核心约束：**永远不等于同意的清单**（§4）是硬红线，任何剧情不得突破；同时不得出现露骨性行为细节。

## 1. 适用对象：只对明确成年角色

亲密 / 恋爱内容只对**明确成年**的角色开放 `[任务卡 §37]`。

- 判定依据：`RelationshipProfile.adult === true` `[CANON]`（现有档案中 sakura_yuko 已标记 `adult: true`）。
- 未明确标记成年、或不满足成年设定的角色：禁止任何亲密内容，恋爱线也不得推进 `[CANON]` 档案判定 + `[PLANNED]` 场景落地。
- 角色模板第 2 项「成年状态」必须显式填写，作为亲密内容白名单前提。

## 2. 允许内容清单

以下内容在满足成年前提下允许出现 `[任务卡 §37]`：

```text
1. 暧昧
2. 调情
3. 拥抱
4. 接吻
5. 温泉 / 灵浴氛围
6. 换装 / 整理装备时的性张力
7. 同寝氛围
8. 吃醋
9. 成人情侣暗示
10. 双方自愿的主人 / 宠物角色扮演
11. 双方自愿的轻度命令 / 服从调情
```

所有允许内容共同边界：**不写露骨性行为细节** `[任务卡 §37]`——允许营造氛围与张力，禁止展开性行为过程的露骨描写。

## 3. 自愿前提

允许清单中的"角色扮演 / 命令服从调情"（第 10 / 11 项）均以**双方自愿**为唯一前提：

- 自愿必须由玩家与角色双方都明确参与，且剧情给出自愿成立的依据。
- 命令 / 服从仅停留在"轻度调情"层面，不得越过氛围进入胁迫或控制叙事。

## 4. 永远不等于同意的清单（硬红线）

以下情境**永远不等于恋爱 / 成人同意**，不得据此展开任何亲密或成人内容 `[任务卡 §37]`：

```text
- 战败
- 被救
- 魅惑
- 精神控制
- 魔法契约
- 强制身份
- 失去行动能力
```

即：任何借助上述状态获得的"亲近 / 亲密"都不构成同意，剧情不得把它们当作推进恋爱或成人内容的正当理由；反之，这些状态也不得被当作惩罚性或榨取性叙事目标。

## 5. 与角色模板的衔接

角色档案（模板 §26）中与本文件相关字段按以下口径填写：

- 「恋爱节奏」：任何阶段不得依赖 §4 清单中的状态推进 `[任务卡 §37]`。
- 「成年亲密事件」：只允许位于 §2 允许清单内的内容，且角色必须 `adult === true` `[CANON]` 判定。
- 「禁止写崩点」：包含 §4 全部条目以及"露骨性行为细节"为写崩点红线。

## 6. 落地实现规则（供实现参考）

1. 亲密 / 成人剧情入口先校验角色 `adult === true`，不满足则拒绝进入 `[CANON]` 档案 + `[PLANNED]` 入口。
2. 涉及允许清单第 10 / 11 项的角色扮演 / 命令服从调情：剧情须先确立双方自愿（有明确双向参与依据）。
3. 成文前逐条核对：§2 允许清单通过、§4 禁止清单未命中、无露骨性行为细节——三项全部满足才放行。
4. 触发与同意分离：战败 / 被救 / 魅惑 / 精神控制 / 魔法契约 / 强制身份 / 失去行动能力等状态一律不作为亲密触发条件。
5. 恋爱与伙伴是相交但独立的两套状态（§38 第 10 项）：亲密事件不得用于强迫改变关系档位；关系档位由既有数值与显式 flag 决定（relationship_rules.md）`[CANON]`。
