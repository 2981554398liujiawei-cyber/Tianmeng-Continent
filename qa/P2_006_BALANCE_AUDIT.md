## 0. 冻结公式摘要（Combat V3，TM-P2-002）

| 项 | 公式 | 位置 |
| --- | --- | --- |
| 属性修正 | `floor((score - 10) / 2)` | `d20.ts getAttributeModifier` |
| 玩家攻击力 | `max(1, 4 + STR修正 + 武器加成 + floor((level-1)/2))` | `combat.ts getPlayerAttackPower` |
| 玩家护甲 | `max(0, 10 + CON修正 + 防具加成)` | `combat.ts getPlayerArmor` |
| 玩家敏捷 | `AGI` 原值 | `combat.ts getPlayerAgility` |
| 命中 | 天然 1→大失败(0)；天然 20→暴击(raw×2)；其余 `(攻击方AGI+roll)/2 >= 防守方AGI` → 命中，否则擦伤(raw×50% ceil) | `resolveHit` |
| 护甲减伤 | 非 MISS：`final = max(1, ceil(raw × roll/(armor+roll)))` | `applyArmor` |
| 先手 | `D20+AGI` 高者先；平局 AGI 高者先；仍平玩家先 | `resolveInitiative` |
| 角色初始 | HP=`10+CON`，MP=`max(0, MND-2)`；升级 +2 maxHp / +1 maxMp | `character.ts` / `progression.ts` |
| 技能 rawDamage | 法师 `max(1,6+MND修正)+等级加成`（MP2）；骑士 `攻击力+2`（MP2）；游侠 `4+AGI修正+武器+等级+2`（MP0，每场一次）；战士 `攻击力+1`（MP2，命中/暴击压制反击） | `skill.ts resolveSkillRawDamage` |

> 注意：`skills.ts` 中法师法术描述为「max(1, 6 + MND修正) + 等级伤害加成」，但 `combat.ts getMageSpellDamage` 本身**不含**等级加成；正式结算走 `skill.ts resolveSkillRawDamage`（含等级加成）。二者一致以 `resolveSkillRawDamage` 为准（模拟器已按此实现）。

## 6. 当前最可疑的数值问题（按严重度排序）

### P1｜敌人 attackPower 全表过低，玩家对任何敌人无死亡风险
敌人每击期望伤害仅 1.05–1.90（护甲减伤 `ceil(raw×roll/(armor+roll))` 在 armor 11–16 下把 atk 2–5 压到个位数以下），而玩家 2–6 击即可结束战斗。模拟铁证：**Lv1 战斗向 build 打 Lv5 骷髅战士胜率 100%**；20 个同级配对全部 ≥ 99%。这是最根本的问题：护甲公式与敌人攻击力的组合使敌人输出趋近于零。

### P2｜强制用例失败：Lv2 LUCK-heavy（战斗属性仅 8–10）打 Lv5 骷髅战士胜率 90.4%–98.8%
跨 3 级、刻意削弱的极端 build 依然几乎必赢，说明「等级」「属性投入」「build 取舍」在当前数值下全部失去意义。骷髅战士（HP20/atk4/armor13）在 Lv2 玩家（HP20-22、普攻 5–6）面前仅能造成 ~2/击 的伤害，需 10+ 击才能击杀，而玩家 6–8 击即结束战斗——等级差完全没有被数值体现。

### P3｜同级战斗 100% 无风险，失败只存在于理论极端骰运
全部同级配对胜率 ≥ 99%（FLAG_TRIVIAL）。敌人需要 10–20 击击杀玩家，但只能活 2–6 击；只有玩家连续多轮「天然 1 大失败」才可能翻车（0.05^n 概率）。战斗系统作为核心玩法循环没有任何张力：药水、防具、技能资源管理均无实际价值（装备对照 Δ0.0pp 佐证）。

### P4｜装备/经济完全无效：可购防具胜率提升 0，锁子甲 55 金开局买不起
50 初始金币：硬皮甲 30 金、法袍 40 金可购，锁子甲 55 金需先攒钱。但模拟显示任何可购防具对胜率提升 **Δ0.0pp**（因胜率已 100%），金币与装备系统成为纯摆设。

### P5｜LUCK 属性在战斗零收益，build 分化形同虚设
LCK 不进任何战斗公式（命中/暴击是天然 1/20，与 LCK 无关；护甲、命中、伤害均不读取 LCK）。LUCK-heavy build 只是「战斗属性纯亏损版」（攻击 -33%、HP/护甲略降），惩罚过轻（仍 90%+ 碾压 Lv5）又无任何战斗回报，玩家必然全堆战斗属性。

### P6｜职业技能价值倒挂：游侠（MP0 每场一次）最强，法师（MP2）最弱
游侠迅捷突袭 raw 11（Lv1）为四职业最高且 MP0；法师法术 raw 9（Lv1）需 MP2，法师普攻仅 5。骑士重击 +2 与战士压制 +1 同为 MP2，但战士多一个「命中/暴击压制反击」特性——技能设计上战士/游侠明显优于骑士/法师，职业平衡倾斜。

### P7｜法师描述与实现不一致 + 攻击成长脱节
`skills.ts` 描述「max(1, 6 + MND修正) + 等级伤害加成」与 `combat.ts getMageSpellDamage`（无等级加成）不一致，正式结算走 `resolveSkillRawDamage`（含加成）——文档与实现存在漂移风险。且玩家攻击力每 2 级才 +1，护甲永不成长，5 级成长（攻击 +2、HP +8）对战斗曲线贡献微弱。

## 7. 调参建议方向（仅建议，不修改任何 src 文件）

1. **敌人 attackPower 需整体上调一个量级**（尤其 Lv3–5 敌人，目标每击期望 4–7），或下调护甲公式减伤强度（如 `raw/(1+armor/k)` 形态），使同级战斗胜率落入 60%–85% 区间。
2. **让等级差产生实质差距**：跨级敌人（如 Lv5 vs Lv2）应能把玩家逼入「须用药水/技能资源」的苦战，强制用例目标胜率 ≤ 50%。
3. 装备/金币：提高防具对「每击期望伤害」的可见影响，或给敌人更高攻击力使护甲差值有意义；锁子甲价格与初始金币的落差需复核。
4. LUCK：若保留「幸运」语义，应让 LCK 影响暴击率/擦伤补偿等战斗参数，否则战斗 build 只剩一维。
5. 技能：复核法师/骑士 vs 游侠/战士的性价比（MP 消耗、伤害、特性）。

> 完整 Before 数据见 `qa/P2_006_BALANCE_REPORT_BEFORE.md`；完整 After 数据见 `qa/P2_006_BALANCE_REPORT_AFTER.md`；复现命令：`node qa/p2-006-balance.mjs --phase before` / `node qa/p2-006-balance.mjs --phase after`（Node 22.15+，种子 20250206，每 pairing 10000 次）。
